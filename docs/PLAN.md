# แผนพัฒนา

1. ตรวจรุ่น ระบบ และ SHA-256 ของแอปจีนต้นฉบับแต่ละแพลตฟอร์ม โดยไม่รวมแอปใน repository
2. แยกคำแปลที่จัดทำเองออกจากโค้ดและการแก้ระบบของแพตช์ภาษาอังกฤษ ตรวจที่มาของแต่ละรายการ
3. เขียนตัวแพตช์ใหม่: ตรวจฐานที่รองรับ, dry run, ตรวจตำแหน่งข้อความอย่างเจาะจง, สำรองก่อนแก้, ติดตั้งและย้อนกลับพร้อมตรวจ checksum ปฏิเสธฐานที่ไม่รู้จัก
4. ตรวจ syntax, keys, placeholders, archive integrity, diff เฉพาะข้อความ, reproducibility และ idempotence แยกแต่ละระบบ
5. ทดสอบติดตั้งและย้อนกลับบนสำเนาต้นฉบับ แล้วทดสอบฟอร์มสิ่งที่ต้องทำ/กำหนดการ การบันทึก แก้ไข ซิงค์ เชื่อมต่อ mirroring และโอนไฟล์ บันทึกข้อที่ทำไม่ได้ตามจริง
6. ตรวจชุดแจกว่าไม่มีแอป vendor, ข้อมูลผู้ใช้, credentials, ไฟล์สำรอง หรือโค้ดที่ไม่มีสิทธิ์แจก แล้วจัด release แยก Windows/macOS พร้อม checksum และคู่มือ

ไม่แก้ business logic, protocol, ระบบเชื่อมต่อ หรือ code signing และไม่ปิดระบบป้องกันของระบบปฏิบัติการ หากฐานแอปไม่รองรับการแก้โดยข้อจำกัดนี้ ให้หยุดและรายงาน

ข้อความจากโทรศัพท์หรือบริการภายนอกต้องระบุแหล่งที่มา ไม่รับรองว่าตัวแพตช์ในเครื่องจะแปลได้
